# Context Charter

## Proposito
Este repositorio es la fuente de verdad del contexto estrategico, tecnico y operativo.

## Principios
- Una sola verdad: evitar duplicados conflictivos.
- Trazabilidad: toda decision importante deja huella.
- Continuidad: el contexto sobrevive a personas, chats y sesiones.
- Simplicidad: preferir documentos cortos y accionables.
- Vigencia: documento sin dueno ni fecha se considera riesgoso.

## Reglas de edicion
- Todo cambio relevante debe incluir `fecha`, `owner` y `motivo`.
- Cambios de arquitectura requieren ADR.
- Cambios de operacion requieren actualizacion de SOP/playbook.
- Los prompts base no se cambian sin registrar impacto esperado.

## Definicion de Done para contexto
Un cambio de contexto esta completo cuando:
1. El documento objetivo quedo actualizado.
2. Hay referencia cruzada en el indice correspondiente.
3. Se registro impacto (arquitectura, operacion o negocio).
4. Existe fecha y responsable.
